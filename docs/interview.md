## 30 秒介绍

我做了一个面向工业维修短文本的抽取系统。用公开的 MaintIE 把文本转换为对象、活动、状态、过程和属性五字段 JSON。我用 Qwen3‑0.6B 做 LoRA，验证了 Loss Mask、参数更新和 Adapter 重载，并用同一模型做三组抽取对照和 KV Cache 基准。FastAPI 把可验证的结果交给工单审核。

## 1 分钟介绍

我参考博世公开的 Equipment Ticket Agent，从记录格式不一致这个痛点切入。目标是将维修短文本里的实体变成下游系统可消费的固定 JSON，我选择了同时有 Gold 与 Silver 标注的 MaintIE。首先审计标注跨度，处理 Gold 与 Silver 的重复和近重复，并冻结测试集。训练阶段用 TRL 和 PEFT 对 Qwen3‑0.6B 做 LoRA，检查只有 completion 参与监督，并验证参数真实更新。随后同一底座用同一批样本比较 Zero-shot、Few-shot 与 LoRA，分别报告格式通过率和实体 F1。部署时我把抽取暴露成 FastAPI，用版本 Manifest 管理 Adapter，并控制生成 token 数来对比 KV Cache。

## 3 分钟介绍

这个项目解决的是维修记录里的信息统一问题。维护人员写的短文本可能同时有设备、部件、状态、动作和过程，后续统计、检索或分发需要反复整理。我先把业务范围定在工单信息抽取和草稿审核，根据公开 MaintIE 标注约定模型目标，再在同一底座上做训练和部署。

数据上，我读取了原始发行文件，按 token 跨度和原文交叉检查，只保留可追溯的五个实体类别。Silver 是上游模型预标注再人工复核，Gold 用于验证和测试。我在划分之前隔离原文与跨度不一致的记录，排除跨语料精确重复和定义内的近重复，保存每组的样本 ID 和文件哈希。测试集的答案不会进入示例或调参。

训练上，我选了一台消费级显卡能复现的 Qwen3‑0.6B 路线。用 PEFT 冻结模型主体，对 attention 的四类投影加 LoRA，再由 TRL 用 completion-only loss 学 JSON 答案。核验时我同时看三个信号：训练批次里的 labels，LoRA 权重实际变化，以及独立进程路径能加载 Adapter 生成结果。训练结束后，我用相同任务、相同样本比较三种模式，用 JSON/Schema 通过率与实体 F1 分开看格式和内容。

部署时，FastAPI 启动一次加载模型，保留原文校验和版本信息，知识查找、审批等业务环节可以独立演进。我用固定生成 token 数对比 Cache 开关，区分单请求延迟、tokens/s 和峰值显存。业务使用方最终收到一份待审核草稿，可核对每个实体的来源。陈述时补充实际运行范围与结果，例如何时完成了 GPU 正式训练、测试集多少条、平台是否真的运行了容器。

## 32 个高价值问题与答案

1. **为什么选工单抽取？** 成熟工单系统需要字段稳定，且有真实标签支撑定量验收。
2. **与博世案例的关联是什么？** 以公开 Equipment Ticket Agent 的工单质量诉求为背景，复现其中一个可离线评测的环节。
3. **为什么使用公开短文本？** 它有细粒度专业标注和版本，适合控制业务范围及复现。
4. **Gold 与 Silver 的主要差别？** Gold 是细粒度专家标注。Silver 来自上游模型预标注并由单人复核。
5. **为什么根标签保留五类？** 两份语料都能映射，业务字段可解释，同时保留较少出现的 Property。
6. **如何判断 token offset 正确？** 使用左闭右开的切片，检查边界、词条以及原文中是否存在该跨度。
7. **如何防数据泄漏？** 在划分前检测精确与定义内近重复、固定分组和随机种子，只从训练集选 few-shot。
8. **还有什么泄漏局限？** Silver 的预标注器见过细粒度语料，这不是跨来源外部验证。近重复筛查也有规则边界。
9. **为什么不用商用 API 做核心？** 本地底座让训练、缓存对照和部署围绕同一权重完成，可归因且易复现。
10. **什么时候 Few-shot 就够？** 验证集接近业务门槛、Prompt 易维护且输入成本可接受时。
11. **什么时候值得做 LoRA？** 当表现问题集中在固定标签、格式或稳定的抽取行为，且已有足够标注样本。
12. **SFT 与 LoRA 有什么区别？** SFT 定义监督训练任务，LoRA 定义可更新的参数形式。
13. **LoRA 如何减少训练参数？** 原线性层冻结，权重更新受限为低秩矩阵乘积。
14. **rank、alpha、dropout 分别控制什么？** 更新容量、增量缩放和 Adapter 训练正则化。
15. **为什么选择 Q/K/V/O？** 它们是清晰且有典型代表性的注意力投影层；其他层可在资源和验证结果允许时再消融。
16. **什么是 Loss Mask？** 将不参与监督位置的 labels 设成 -100，模型仍能读取这些位置的 Prompt。
17. **怎么核验 Loss Mask？** 检查实际 collator batch 和模板边界，把有效 token 解码成完整 JSON。
18. **为什么始终记录真实步数？** 梯度累积下一个 batch 并不等于一次参数更新，实际步数由 Trainer 状态记录。
19. **为什么没用 QLoRA？** 当前目标用短序列与 BF16 小模型即可验收，量化会引入额外后端和实验变量。
20. **为什么训练不使用 KV Cache？** 整段训练并行计算，缓存面向逐 token 推理，并会增加训练内存。
21. **Adapter 和 Checkpoint 有何区别？** Adapter 存低秩权重用于复用；检查点还可保存训练状态和优化器以便续训。
22. **怎么评估无效输出？** 仍计入总样本，并作为空预测计实体漏抽，避免选择性保留样本。
23. **实体 F1 的匹配规则是什么？** 类别和归一化文本组成集合元素，统一大小写与空白，保留标点。
24. **Micro 和 Macro 为什么都报？** Micro 反映整体实例表现，Macro 让稀有类别也影响平均分。
25. **如果 LoRA 低于基线怎么办？** 检查原始失败样本、类别支持、模板、学习率及时训练长度，在验证集迭代，如实报测试结果。
26. **Prefill 与 Decode 的差别是什么？** Prefill 先处理整个输入并填缓存，Decode 从已有上下文逐步生成 token。
27. **KV Cache 实验如何公平？** 同权重、精度、输入、生成参数和实际 token 数，预热交替重复并同步 GPU。
28. **为什么区分 tokens/s 和并发吞吐？** 单请求生成速度只覆盖顺序解码，吞吐须在明确的并发或批处理设置下测。
29. **怎么控制错误进入工单系统？** 严格 Schema、原文校验、可追溯模型版本以及独立的人工审核。
30. **怎么管理版本和回退？** 固定底座 revision、数据和 Adapter 哈希，服务启动按 Manifest 校验，回退时切换并重启。
31. **CI 为什么不下载模型？** 用轻量测试覆盖数据逻辑和接口契约，模型是否真实可运行由独立验收提供证据。
32. **何时考虑 RAG 或迁移到供应链？** 需要查询动态知识时加入带来源检索，迁移领域时先定义新 Schema、取得代表性标注并重新验收。
